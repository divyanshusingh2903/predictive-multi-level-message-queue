# Production-readiness roadmap

## Summary
Harden the existing Phase 1 broker before adding ML routing or benchmark claims. Prioritize delivery correctness, bounded resources, secure RPC behavior, lifecycle handling, and automated release validation.

## Context / Findings
- Core MLFQ, TTL, retry, DLQ, ownership, and aging behavior is implemented and has 79 passing local tests.
- There is no CI, sanitizer coverage, benchmark harness, or executable ML engine.
- `src/consumer/consumer.cpp` ignores Ack/Nack RPC status and allows handler exceptions to escape.
- `src/pmlmq_service.cpp` has no in-flight lease/recovery, a Pull cancellation/orphaning risk, and unbounded broker-owned state.
- Clients lack consistent RPC deadlines and safe retry/idempotency semantics.
- The server and `InspectDlq` endpoint are insecure/unauthenticated for production use.
- Configuration validation and background-thread shutdown behavior need tightening.

## Approach
Treat this as a staged Phase 1 release gate: first make every message outcome recoverable and every resource bounded, then secure and observe the service, and finally automate clean-build and concurrency validation. Defer ML implementation until these guarantees are established so model failures cannot obscure broker correctness.

## Files affected
- `src/consumer/consumer.cpp`, `include/consumer.hpp` — handle handler failures and Ack/Nack RPC errors explicitly.
- `src/pmlmq_service.cpp`, `include/pmlmq_service.hpp` — define atomic ownership transitions, lease expiry/recovery, capacity accounting, and lifecycle behavior.
- `src/queue/multi_level_queue.cpp`, `include/queue/multi_level_queue.hpp` — enforce capacity/shutdown semantics and replace interruptible-thread sleeps.
- `src/queue/dead_letter_queue.cpp`, `include/queue/dead_letter_queue.hpp` — add bounded retention and consistent pagination/accounting.
- `src/producer/producer.cpp`, `src/proxy/proxy.cpp`, `proto/pmlmq.proto` — add deadlines and idempotent mutation semantics where retries are supported.
- `server/main.cpp` — secure transport/authentication and startup/readiness failure handling.
- `tests/unit/`, `tests/integration/` — add failure, race, limits, recovery, and shutdown coverage.
- `CMakeLists.txt`, `tests/CMakeLists.txt`, `.github/workflows/` — reproducible CI, sanitizer, static-analysis, and formatting gates.
- `README.md` and operational documentation — document supported toolchain, limits, security, recovery, and release criteria.

## Step-by-step implementation
1. Define production semantics and configuration: lease duration, redelivery/retry behavior, queue/in-flight/DLQ/payload limits, backpressure response, shutdown/drain policy, and secure deployment boundary.
2. Fix client delivery handling: validate handlers, catch exceptions, check Ack/Nack status, and define recovery when acknowledgement RPCs fail.
3. Add broker-side in-flight leases and recovery; close Pull cancellation races and test ownership state transitions under concurrency.
4. Add centralized capacity accounting and backpressure across Submit, requeue, and DLQ paths; reject invalid configurations early.
5. Add deadlines, authentication/TLS, authorization for operator APIs, and idempotency keys before enabling mutating RPC retries.
6. Replace polling sleeps with stop-aware condition-variable/token wakeups and verify bounded shutdown, restart, and graceful-drain behavior.
7. Add metrics, structured payload-free logs, tracing hooks, and health/readiness signals for queue, in-flight, retry, TTL, DLQ, and backpressure states.
8. Add CI with clean dependency configuration, Debug/Release builds, CTest, ASan/UBSan, TSan, formatting, and static analysis.
9. After the release gate passes, implement the ML interface and feedback sink at `route_message()`, then build reproducible FIFO/static-priority/round-robin/MLFQ benchmarks.

## Risks / edge cases
- Lease recovery and cancellation fixes can cause duplicate delivery or message loss unless ownership transitions are explicit and stress-tested.
- Retrying Submit without idempotency can duplicate messages.
- Limits must cover initial enqueue, retries, and DLQ admission consistently.
- Timing-sensitive TTL/aging tests may flake; prefer injectable clocks or deterministic synchronization.
- TLS/auth and observability changes must avoid payload leakage and excessive hot-path contention.

## Testing strategy
- Add named regression tests for handler exceptions, failed Ack/Nack, Pull cancellation, lease expiry/recovery, wrong-owner races, duplicate mutations, shutdown, config validation, and capacity boundaries.
- Run concurrent producer/consumer stress tests plus repeated TSan runs; use ASan/UBSan for memory and undefined behavior.
- Add integration tests for authentication, deadlines, readiness, graceful drain, and operator authorization.
- Require clean configure/build/test in CI and retain machine-readable results.
- Validate ML and benchmark work only after the release gate, with reproducible seeds and P50/P95/P99, throughput, starvation, and prediction metrics.
