# P1 — TTL-Expiry-at-Pull: Tests + Hardening

## Summary
Make TTL expiry correct, observable, and covered end to end: per-message TTL
on `Submit`, reclamation of never-pulled expired messages, expiry-first
`Nack`/`Ack` semantics, and a read-only `InspectDlq` RPC — plus the missing
`BrokerTest` expiry cases. Full-hardening scope, user-confirmed.

## Context / Findings
- `Message::is_expired()` is `ttl != 0 && now - arrival_time >= ttl`
  (`include/queue/message.hpp:22-40`, steady clock). TTL runs on
  `arrival_time` (stamped once by `Proxy::accept`, never reset); aging runs on
  the separate `enqueue_time` (reset on every `enqueue`/promotion/requeue).
- `Proxy::accept` (`src/proxy/proxy.cpp:25-39`) is narrow by contract
  (`include/proxy/proxy.hpp:14-17`): stamps ID + `arrival_time`, forwards to
  the routing sink, knows nothing of TTL.
- `route_message` (`src/pmlmq_service.cpp:33-41`) is the single routing point:
  sets `priority`/`original_priority`/`max_retries`, applies `default_ttl`
  when the message carries none. Future ML injection point.
- `SubmitRequest` (`proto/pmlmq.proto:25-29`) has no TTL field and
  `Producer::send` (`include/producer/producer.hpp:34-35`) takes
  payload + headers only — TTL is controllable solely via
  `PMLMQConfig::default_ttl` (off by default; `server/main.cpp` and
  `demo/main.cpp` both use 0). `ttl == 0` conflates unset with explicitly off.
- `Pull` (`src/pmlmq_service.cpp:92-153`) is the ONLY expiry checkpoint
  (wait capped at `max_pull_wait`, 100 ms poll chunks, expired → DLQ
  `TTL_EXPIRED` + keep scanning). Nothing else checks expiry: not queue
  `dequeue`/aging, not `Ack`/`Nack`. Consequences: never-pulled expired
  messages leak and aging promotes them toward L0; `Nack`-after-TTL requeues a
  dead message or mislabels it `MAX_RETRIES_EXCEEDED`; `Ack`-after-TTL
  silently succeeds.
- DLQ read API is destructive `pop()` only
  (`include/queue/dead_letter_queue.hpp`); no peek — DLQ reasons are
  unverifiable from outside.
- Coverage: queue 14 tests, DLQ 8 (TTL_EXPIRED as opaque enum only), broker
  11, client 13 — all assert DLQ size solely for max-retries. Zero TTL-expiry
  tests. `test_broker.cpp:226-258` shows the local-service pattern for
  custom-config tests.

## Approach
One slice, ordered so `main` stays green at every step. Proxy stays narrow
(opaque TTL passthrough, no config reads); `route_message` stays the only
place defaults apply (sentinel resolution only). The queue stays DLQ-agnostic
via a `sweep_expired()` primitive the service drains. Ownership checks keep
precedence over expiry in `Ack`/`Nack`. User decisions baked in: Ack-after-
expiry lands in DLQ (client still sees OK); DLQ observability is a full
`InspectDlq` gRPC RPC.

## Step-by-step implementation
1. DLQ `snapshot()` + service forwarding + container tests (peek twice same
   ID, size unchanged, FIFO order). No behavior change.
2. Proto `optional ttl_ms` + regen + `Producer::send` overload (old `send`
   delegates with nullopt; old clients = unset). Test: negative
   `ttl_ms = -5` → `INVALID_ARGUMENT`, `queue_size == 0`.
3. `Proxy::accept` overload + `route_message` sentinel resolution
   (`kTtlUnset` → `default_ttl`; explicit `0` stays off; positive passes
   through). Tests: proxy unit (unset→sentinel, values passthrough);
   unset→default, explicit-0 beats default, per-message beats off-default.
4. `MultiLevelQueue::sweep_expired()` (single lock, per-level stable
   partition, size accounting) + aging skips expired. Unit tests: mixed TTLs
   across levels, only-expired returned in level order, expired never
   promoted (`size(0) == 0`).
5. Service sweeper thread (ctor start, dtor join before queue shutdown;
   `ttl_sweep_interval{100 ms}`, `0` disables) + sweep at each `Pull`-chunk
   top (deterministic tests; sweeper is the idle-consumer backstop). Tests: 5
   never-pulled messages → `queue 0, dlq 5` with no `Pull` (wait-for, not
   fixed sleep).
6. `Nack` expiry-first (after ownership checks, before `retry_count++`; DLQ
   `TTL_EXPIRED` with caller reason; count untouched) + `Ack`-after-expiry →
   DLQ `TTL_EXPIRED`, client still `OK`. Tests via `InspectDlq`: Nack-after-
   TTL → `TTL_EXPIRED` (not `MAX_RETRIES`, not requeued); Nack-before-TTL
   requeues and delivers; Ack-after-TTL → `OK`, `dlq 1`, `in_flight 0`.
7. Core expiry-at-Pull cases (local-service pattern; `ttl = 100 ms`, sleep
   300–400 ms, `Pull` 500–1000 ms, client deadline 3 s): expired →
   `timed_out` + `dlq 1` + `queue 0` + `in_flight 0`; `TTL = 0` control
   delivers after 300 ms; expired head skipped, fresh delivered, second `Pull`
   times out; 3 expired drained in one `Pull` (`dlq 3`).
8. `InspectDlq` RPC (reason/payload/headers mapping, limit/offset with cap,
   `dlq_age_ms` — `dlq_time` is steady-clock so no fake unix time; no-auth
   operator endpoint, documented) + pagination tests.
9. Docs: `AGENTS.md` invariants (sentinel lifetime, clock discipline, Nack
   precedence, RPC cap) + TTL example in demo.

## Risks / edge cases
- Conda `protoc` 29.3 shadows `/usr/local` 31.1 on default PATH — configure
  and build with sanitized PATH (`/usr/local/bin` first,
  `-DCMAKE_PREFIX_PATH=/usr/local` per P0). `optional` needs protoc ≥ 3.15.
- Timing flake: assert `timed_out` + counters only, never elapsed time; rerun
  new tests 3×. `ttl < 50 ms` or sleep `< 3× TTL` is flaky territory.
- Sentinel leak safety: `is_expired() <= 0` means a leaked `kTtlUnset` can
  never falsely expire; plus `DCHECK` post-resolution in `route_message`.
- Ownership/error precedence unchanged and before expiry: unknown consumer →
  `PERMISSION_DENIED`, unknown ID → `NOT_FOUND`, wrong owner →
  `PERMISSION_DENIED`. Expiry never masks auth bugs.
- Untouched: priority semantics, ML hook shape, consumer tier-blindness (no
  level/TTL in `PullResponse`), `arrival_time` immutability, `Pull` wait cap /
  chunk / cancel semantics, `default_ttl = 0` default, DLQ never redelivers
  (no replay in P1), `processing_time_ms` (Phase 2).

## Testing strategy
- Clean rebuild exits 0 with proto regen, no new warnings.
- `./build/tests/pmlmq_integration_tests --gtest_filter='BrokerTest.*'`:
  11 existing + ~14 new pass, 3 consecutive runs.
- `ctest --test-dir build` fully green; `./build/demo/pmlmq_demo` ends with
  queue 0 / in-flight 0.
- `InspectDlq` reason assertions distinguish `TTL_EXPIRED` from
  `MAX_RETRIES_EXCEEDED` on the Nack/Ack-path tests.
