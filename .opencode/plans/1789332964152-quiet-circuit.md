# Unblock Build — Step 1 (Protobuf CONFIG Link Fix)

## Summary
Fix the `absl::Cord` link failure for `pmlmq_server`, `pmlmq_integration_tests`, and `pmlmq_demo` with a 1-line CMake change (`find_package(Protobuf CONFIG)`), keeping the modern `/usr/local` trio. Clean rebuild, then verify all binaries + tests.

## Context / Findings
- `CMakeLists.txt:14` uses Module-mode `find_package(Protobuf)` → bare `/usr/local/lib/libprotobuf.a` with no absl transitive deps; `:15` uses CONFIG `gRPC` which emits ~80 `libabsl_*.a` first.
- `build/CMakeFiles/pmlmq_server.dir/link.txt` shows `libprotobuf.a` last (pos 111/112), after `libabsl_cord.a` — single-pass `ld` cannot resolve `Cord::EstimatedMemoryUsage` refs (54 undefined refs in `libprotobuf.a`).
- `pmlmq_unit_tests` links only via `--as-needed` (no gRPC symbols referenced); server/demo/integration force `pmlmq.pb.cc.o` extraction and fail.
- Rich CONFIG target exists at `/usr/local/lib/cmake/protobuf/protobuf-targets.cmake` (`protobuf::libprotobuf` STATIC IMPORTED + ~35 `absl::*` deps).
- Three protoc stacks compete: `/usr/local` 31.1 (correct), apt 3.21.12, conda 29.3 first in `PATH` — must sanitize.
- Existing `.opencode/plans/link-order-config-fix.md` already details this; apt-switch alternative rejected (downgrade + install).

## Approach
One-line root-cause fix: switch to `find_package(Protobuf CONFIG REQUIRED)` so CMake topologically sorts `libprotobuf.a` before its absl deps via `pmlmq_proto`. No source/proto changes; mandatory clean rebuild to drop stale `Protobuf_LIBRARY_*` cache.

## Files affected
- `CMakeLists.txt:14` — `find_package(Protobuf REQUIRED)` → `find_package(Protobuf CONFIG REQUIRED)`
- `build/` — deleted and regenerated (cache wipe required)

## Step-by-step implementation
1. Edit `CMakeLists.txt:14` to CONFIG mode; leave `:15`, `:30`, `:41`, `:64`, `demo/`, `tests/` untouched.
2. Sanitize env: `conda deactivate`, verify `which -a protoc` lists `/usr/local/bin/protoc` (31.1) first.
3. `rm -rf build && cmake -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=/usr/local && cmake --build build -j$(nproc)`.
4. Audit `build/CMakeFiles/pmlmq_server.dir/link.txt`: `libprotobuf.a` must precede `libabsl_cord.a`; no `/usr/lib` or conda mixing.
5. Run `./build/tests/pmlmq_unit_tests` (31/31), `./build/tests/pmlmq_integration_tests` (26 tests), `./build/demo/pmlmq_demo` (DLQ≈0, retries>0), `ctest --test-dir build`.

## Risks / edge cases
- Reusing `build/` without wipe keeps Module-mode vars → fix silently not applied.
- CONFIG requires `/usr/local/lib/cmake/protobuf/`; fails on Module-only images (not the case here).
- Conda reactivation re-shadows protoc 29.3 → version skew.

## Testing strategy
- Clean rebuild exits 0, no `absl::Cord` undefined refs on all 3 previously-failing targets.
- `ctest --test-dir build` green; `link.txt` order audit passes.
